ARCHITECTURE SUMMARY (must be understood before reading sub-tasks)
================================================================================

  - SINGLE TABLE design: `inbound_event` only (no event_log, no dead_letter_event)
  - NO outbox pattern: Kafka publish is synchronous within the HTTP request
  - NO event type normalization: Collector strictly validates type matches
    `org.openphc.cce.<resource>` — normalization is the emitter adaptor's
    responsibility (openHIM mediator layer)
  - NO field name mapping: CloudEvents lowercase field names are preserved
    end-to-end (HTTP → DB → Kafka) — no camelCase translation
  - Rejection tracking: directly on `inbound_event` via status, rejection_reason,
    failure_stage, error_details, resolved, resolved_at columns
  - Content type branching: `application/fhir+json` (FHIR R4 validation),
    `application/json` (JSON validity check), other → reject
  - Kafka failure: returns HTTP 500, source system retries (no background retry)
  - Single Flyway migration: V1__create_inbound_event.sql

  1. V1__create_inbound_event.sql
     - Table: inbound_event
     - Columns (21):
       id (UUID PK, gen_random_uuid()),
       cloudevents_id (VARCHAR NOT NULL),
       source (VARCHAR NOT NULL),
       type (VARCHAR NOT NULL),
       spec_version (VARCHAR NOT NULL DEFAULT '1.0'),
       subject (VARCHAR — patient UPID),
       event_time (TIMESTAMPTZ),
       data_content_type (VARCHAR DEFAULT 'application/fhir+json'),
       facility_id (VARCHAR),

       idx_inbound_event_received (received_at)

SUB-TASK C10: Event Ingestion Orchestrator & REST Endpoint
================================================================================

DESCRIPTION:
  Implement the main event ingestion pipeline that orchestrates validation,
  deduplication, persistence, defaults enrichment, payload validation, and
  synchronous Kafka publishing. Expose as POST /v1/events REST endpoint.

DELIVERABLES:
  1. EventIngestionService.java (service/):
     - ingest(EventIngestionRequest request) → EventIngestionResponse
     - Orchestration flow (9 steps per architecture.md § 6):
       1. Parse request body
       2. CloudEvents envelope validation → 400 on failure
       3. Deduplication check → 200 (idempotent) if duplicate
       4. Persist to inbound_event (status=RECEIVED, raw_payload=original)
       5. Event type validation (strict org.openphc.cce.<resource> match)
          → 400 + REJECTED on failure
       6. Apply server-side defaults (correlationid, time)
       7. Payload validation (branched by datacontenttype):
          - application/fhir+json → FHIR R4 validation → 422 on failure
          - application/json → JSON validity check → 422 on failure
          - other → 400 UNSUPPORTED_CONTENT_TYPE
       8. Update inbound_event.status = ACCEPTED
       9. Synchronous Kafka publish
          - Success → HTTP 202 Accepted with receipt
          - Failure → update status=REJECTED, reason=KAFKA_PUBLISH_FAILURE,
            return HTTP 500

  2. RejectionService.java (service/):
     - recordRejection(InboundEvent event, RejectionReason reason,
       FailureStage stage, String errorDetails) → void
     - Updates inbound_event with rejection_reason, failure_stage,
       error_details, sets status = REJECTED

  3. EventIngestionController.java (api/controller/):
     - @PostMapping("/v1/events")
     - Accepts @Valid @RequestBody EventIngestionRequest
     - Returns ResponseEntity<ApiResponse<EventIngestionResponse>>
     - 202 Accepted on success, 200 on duplicate, 400/422 on validation

  4. GlobalExceptionHandler.java (api/exception/):
